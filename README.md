# 太吾异世劫 Wiki 图鉴｜功法、装备、灵侍、宛渠之民与 Build 工坊

链接：https://kechen666.github.io/taiwuyishijie-wiki 

一个非官方的《太吾异世劫》玩家资料站，仅仅用于讨论、学习，不用于任何商业途径。整理功法、装备、角色特质、灵侍、宛渠之民与局内道具，支持关键词反查、Build 配置、换装对比，以及 JSON / PNG 分享。

项目采用原生 HTML、CSS 和 JavaScript，无前端构建步骤、账号系统或后端依赖，可直接通过 GitHub Pages 发布。

## 功能

- **图鉴查询**：功法与升级分支、进化、装备固定词条和随机池、角色境界特质、灵侍成长阶段及局内道具。
- **宛渠之民**：按门派、等级、性格编号筛选人物模板，搜索可能姓名、身份与能力效果；查看基础工作/知识、两个能力池的权重与抽取关系，以及能力对应的人物。特殊人物与停用配置分别标记。
- **关键词反查**：按名称或效果寻找相关功法、装备与特性、角色特质、灵侍、道具和宛渠能力；卡片、精确关键词搜索与详情使用相同的相关记录。
- **Build 配置**：最多 6 门功法、每门最多 3 条升级分支、9 个装备部位，并选择角色、境界特质和随行灵侍。
- **装备对比**：按品阶汇总固定属性上下限，对照换装前后的属性差值与特殊效果变化。
- **掉落机制说明**：解释玩家最终R（`RareEquip_DropRate`）、死亡敌人最终E（`RareEquipmentDropRateAddition`）及独立的数量加成D；比较8条规则在R=0%、100%、150%、250%、350%、450%时的单件绝品概率和每次至少1件绝品概率，提供折线图、对数坐标与数值表。
- **可能联动**：随功法、进化及分支等级动态更新，默认折叠；用于配置规划，实际范围和叠加仍待验证。
- **保存与分享**：支持攻略备注、浏览器本地保存、JSON 导入导出；PNG 依次展示备注、角色与灵侍、功法、装备，不包含可能联动和详细属性合计。

## 数据范围与验证状态

原有图鉴基于 **2026-10-16 的已整理配置快照**；宛渠之民和掉落机制分别采用独立的 **2026-10-17 本地配置/静态分析资料**。源文件不同，本次没有替换原有功法、装备或灵侍数据。收录内容非全部游戏内容，适用游戏版本号尚未确认。

| 分类 | 收录范围 |
| --- | --- |
| 功法 | 30 门基础功法、450 个升级节点、90 个进化 |
| 装备与关键词 | 145 件装备、386 条装备特性、34 个关键词 |
| 角色特质 | 6 位角色、90 个特质 |
| 灵侍 | 7 类普通灵侍、43 条成长阶段、7 条特殊召唤、50 个技能槽记录 |
| 局内道具 | 8 种主动道具、35 种丹药、3 种基础拾取物 |
| 宛渠之民（2026-10-17） | 54 条门派模板、6 条特殊模板（2 条停用）；330 个非空名称条目，328 种显示姓名；40 条对应能力配置 |
| 掉落机制（2026-10-17） | normal、elite、smallboss、bigboss、BaoXiang_H1L1、Equipment_Event、BaoXiangGuai、NiuDa，共8条规则与6个R对照点 |

- **配置描述**：从游戏本地配置提取的说明。
- **待验证**：**机制、触发范围或叠加方式**尚**未确认**。
- **已实测机制**：需要提供游戏版本、测试日期、复现步骤与证据；当前尚无此类记录。

网页自动检查通过不代表游戏机制已实测。

宛渠姓名从名称池抽取，与能力没有固定绑定；每个非空能力池分别加权抽 1 项，池内百分比不等于人物的最终招募概率。工作与知识显示模板基础值，当前能力配置没有直接增加这两个字段。知识对招募与委托的具体换算仍待验证。原始招募池中的重复、错级以及性格编号/显示文本差异均予以保留。

## 更新说明

### 2026-10-17：新增装备掉落机制与概率图表

- 新增 `#drops` 页面及“掉落机制”导航。展示普通怪、精英怪、小BOSS、大BOSS、宝箱H1L1、事件奖励、宝箱怪/宝藏地精、牛大与原规则ID的对应关系。
- 将单件绝品概率与一次击杀/开箱/奖励触发至少获得1件绝品的概率分开，数量层使用最低总件数，并对件数分布求和。
- 提供R=0%、100%、150%、250%、350%、450%的两张折线图、独立E/D输入、曲线显隐、所选规则重点查看、线性/对数坐标及完整数值表。默认E=D=0，默认数量模型为静态整数门槛，可切换名义概率作对照。
- 品质权重同时放大极品与绝品：`K=(1+R)*(1+E)`，R/E不是直接加到绝品率上的百分点。宝箱怪和牛大的单件曲线重合，但每次触发概率不同。
- 宝箱与事件以虚线标为统一公式对照。已追踪的任务奖励调用传D/R/E=0；H1L1具体入口及含义映射尚未确认，因此不能据虚线断言玩家堆R能提升这些奖励。所有结果为配置与静态模型推导，尚无游戏掉落统计实测。

### 2026-10-17：新增宛渠之民图鉴

- 新增导航入口 `#wanqu`，提供门派人物、特殊人物、能力词条三类视图。
- 人物卡片展示可能姓名、等级、性格、工作和知识；详情列出独立能力池、原始权重、池内名义概率及默认招募池记录。
- 能力详情可反查关联人物，并区分启用和停用模板；鸿运当头等涉及掉落的描述附有静态分析提示，不将权重增幅当作掉率百分点。
- 正式宛渠能力接入关键词反查，结果标注独立的数据日期；详情保留源表、Index、原ID及数据库 SHA256。
- 本次仅扩充图鉴查询，Build 方案格式与原有功能保持兼容。新增数据文件随静态站点一起提交即可，继续使用现有 GitHub Pages 发布方式，无需安装前端依赖。
- 按玩家使用需求移除 34 条内部新手/回退/测试模板及其独有的 4 条测试能力，人物与能力反查中也不再包含这些记录。

人物图像核查：宛渠配置引用的是服装、配饰或特殊NPC预制体，没有逐人物图标字段。资源目录中存在 `UIWanQuPeopleModel` 与 `WanQuPeopleCameraWorkSpace`；人物列表的 `AvatorImage` 控件未绑定静态 Sprite。目前未找到能与各人物一一对应、可直接导出的独立头像，页面继续使用文字标识。品级徽章、任务图案及新手引导头像不作为人物专属头像。

## 开发与维护

主要文件：

| 文件 | 用途 |
| --- | --- |
| `index.html`、`wiki-ui.js`、`wiki-tools.css` | 主界面、关键词与联动展示 |
| `build-stats.js`、`wiki-tools.js`、`build-image.js` | 装备统计、关联逻辑、PNG 导出 |
| `guide-ui.js`、`guide-build.js`、`guide.css` | 角色、灵侍、道具与 Build 身份配置 |
| `data.js`、`guide-data.js`、`assets/icons/`、`export-icons.js` | 运行时数据、原图与导出缩略图 |
| `guide-source.json`、`source-links.json`、`mechanics-evidence.json` | 可维护数据源、原配置关联与验证记录 |
| `wanqu-source.json`、`prepare-wanqu-data.py`、`wanqu-data.js` | 宛渠独立维护快照、生成脚本与网页数据 |
| `wanqu-ui.js`、`wanqu.css`、`check-wanqu.cjs` | 宛渠图鉴、筛选与详情交互、数据及回归检查 |
| `drop-source.json`、`prepare-drop-data.py`、`drop-data.js` | 掉落规则快照、来源解释与网页数据生成 |
| `drop-model.js`、`drop-ui.js`、`drop.css`、`check-drop.cjs` | 概率计算、响应式SVG图表、数据表及独立枚举验证 |

维护宛渠数据时保留人物、能力、名称TID及源表Index，编辑 `wanqu-source.json` 后运行：

```bash
python prepare-wanqu-data.py
node check-wanqu.cjs
node check-build.cjs
node check-tools.cjs
node check-guide.cjs
node check-icons.cjs
```

`wanqu-source.json` 来自本地只读采集资料，包含能力池关联、招募池原始位置、工作/知识原文与待验证记录。新增版本应重新核对源SHA与日期；不要只修改日期或去重显示姓名、重复的招募池位置。

维护掉落说明时编辑 `drop-source.json`，运行 `python prepare-drop-data.py` 和 `node check-drop.cjs`，再运行上方原有检查。保留原规则ID、Index、品质权重与来源/验证边界；不要将宝箱H1L1猜测成适用于全部宝箱的确定规则，也不要将统一公式对照曲线当成已确认的入口传参。
